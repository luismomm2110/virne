================================================================================
KEY METRICS EXPLAINED
================================================================================

ORACLE RAC (Request Acceptance Rate):
- Percentage of VNRs where at least ONE algorithm succeeded
- Represents theoretical maximum if we always pick a working algorithm
- Why not 100%? Some VNRs are genuinely unsolvable (no algorithm works)

MODEL TOP-3:
- Accuracy of model's top-3 algorithm recommendations
- Does the model's #1, #2, or #3 recommendation work for this VNR?
- More forgiving than exact classification (allows top-3)

MODEL CLASSIFICATION:
- Exact prediction accuracy - does model exactly predict best_for_rac?
- Most strict metric
- Always lower than Top-3

GAP (Oracle - Model Top-3):
- Shows percentage of solvable VNRs where model fails
- Represents room for improvement in algorithm selection
- Higher gap = more opportunity to improve model

================================================================================
METHODOLOGY
================================================================================

DATASETS USED:
- datasets/test.csv (617 rows) - ML test set
- datasets/vnr_clean.csv (4,500 rows) - All unique VNRs
- datasets/vnr_features.csv (658,222 rows) - Execution results
- models/ranking_results_per_topology.json - Model metrics

MATCHING ALGORITHM:
For each row in test.csv (without v_net_id):
1. Extract features: v_net_num_nodes, v_net_num_edges, v_net_demand
2. Search vnr_clean.csv for matching row with:
   - Same topology
   - Same feature values (with floating-point tolerance)
3. If found: get v_net_id and seed
4. Use these to look up results in vnr_features.csv

ORACLE CALCULATION:
For each matched VNR:
1. Retrieve all algorithm execution results
2. Group by algorithm (take first result per algorithm)
3. Check if ANY algorithm succeeded
4. If yes: count as success; if no: count as failure
Oracle RAC = (successes / total_vnrs) * 100
